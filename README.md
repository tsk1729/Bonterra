# Emergency Assistance Funding

FastMCP stdio backend with organization-isolated SQLite storage, exact USD cents, atomic approval reservations and idempotent simulated payments.

All monetary fields use integer cents: `amount_cents=30001` represents USD 300.01. Zero, negative values and floating-point inputs are rejected.

- [Assignment documentation](docs/solution_design.md): problem, entities, workflows, permissions, requirements, tests, AI approach and limitations.
- [API contract](docs/mcp_api_contract.md): tools, inputs, outputs, errors and examples.

## Setup, test and demonstrate

Python 3.11–3.14; verified on Python 3.14/macOS arm64. Run from the repository root:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps --no-build-isolation -e .
.venv/bin/python -m assistance.seed_database --db data/assistance.sqlite3
.venv/bin/python -m pytest -q
.venv/bin/python scripts/demonstrate_funding_workflow.py --db data/assistance.sqlite3
```

The demo launches separate worker, manager and finance processes, discovers nine tools, creates a $300.00 rent request, approves, pays and retrieves the final summary. On fresh fixtures: allocation $10,000.00; committed $0.00; paid $300.00; available $9,700.00. Each run adds another request. No model/API key is required.

Normal startup (does not initialize or reset storage):

```sh
ASSISTANCE_DB="$PWD/data/assistance.sqlite3" ASSISTANCE_IDENTITY=udaan_case_worker .venv/bin/python -m assistance.mcp_server
```

Stop servers before explicitly replacing synthetic data:

```sh
.venv/bin/python -m assistance.seed_database --db data/assistance.sqlite3 --reset
.venv/bin/python scripts/export_mcp_tool_schemas.py
```

The current database schema is version 8 and stores USD integer cents. Older rupee-based synthetic databases are rejected; use the explicit reset command above to recreate fixtures. Existing amounts are never automatically converted or relabeled. Startup never upgrades or erases storage.

Fixture identities: `udaan_case_worker`, `udaan_program_manager`, `udaan_finance`, and the same three with `asha_` prefix. Udaan has Ananya Sharma and Rohan Kumar; Asha has Kavya Iyer and Arjun Singh. Each organization has emergency ($10,000.00) and transport ($500.00) funds. Local identity configuration and the database are trusted; launching a different fixture intentionally represents a different staff user.

The demo is the reproducible MCP client required by the assignment. It launches separate role-bound servers using the configuration above; identities never appear in tool arguments. Logs use stderr. Clients inspect MCP `isError` for validation/protocol failures and structured `ok/error` for business failures. The `data/` directory is generated by setup and is not part of the submission.

## Review and evidence

[Assignment documentation](docs/solution_design.md) includes requirement-to-code-to-test mapping, actual results, time spent and AI workflow evidence. Raw [test output](evidence/test_results.txt) and [demo output](evidence/funding_workflow_demo.txt) accompany it.

The server keeps balances derived from request states. Every mutation obtains SQLite `BEGIN IMMEDIATE` before reading state or available funding. Payment is a single atomic update of the request status, payer and payment time. The schema has five tables; request ownership is derived through its fund, and full payment needs no separate payment table. Concurrency and cent-precision tests verify budget behavior.

Framework references: [FastMCP tools](https://gofastmcp.com/docs/servers/tools), [stdio clients](https://gofastmcp.com/docs/clients/transports). The pinned installed SDK and executable tests resolve version-specific behavior.
